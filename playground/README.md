# YotsubaShader playground compiler host (Blazor WebAssembly)

The website's playground UI (`/playground/`, `src/static/js/playground.js`) talks to the compiler through a small
backend object. This folder is the .NET side that provides it. Roslyn runs in the browser, so C# diagnostics,
completion, hover, signature help, shader discovery, and the supported compilation path are available through the
connected backend.

```
Monaco (one model per file) ──► YotsubaPlayground backend ──► DotNet.invokeMethodAsync('Playground', ...)
                                                                   │  (WebAssembly)
                                                                   ▼
                                     PlaygroundApi  →  ProjectState (Roslyn AdhocWorkspace)
```

## What works

| Feature | State |
| --- | --- |
| Several `.cs` files (add, rename with double-click or F2, delete), saved in the browser, shareable link | done |
| Live C# diagnostics across files (`Analyze`) | done (Roslyn) |
| Completion, hover and signature help (`Complete`, `Hover`, `SignatureHelp`) | done (Roslyn Workspaces + Features) |
| `Compile`: diagnostics, `ShaderDiscovery.Find`, frontend validation, and supported C# shader compilation | done |
| SPIR-V assembly text in `Compile` | done |
| HLSL, GLSL, GLSL ES, MSL, and C++ output per discovered stage | done |
| IR dump in the browser response | not part of the current contract |

The connected backend returns output for the supported shader subset. Unsupported C# operations, resource paths, or
stage features are returned as diagnostics when the compiler cannot lower them. The playground displays SPIR-V
assembly text; binary `.spv` artifacts are generated by the CLI `compile` command.

## No XNA by default

User code references the .NET 8 reference assemblies (`Basic.Reference.Assemblies.Net80`),
`YotsubaShader.Language` and the selected `YotsubaShader.*Syntax` vocabulary. `Microsoft.Xna.Framework` is **not**
referenced. The default project has two files:

- `Types.cs`: your own `Vector2/3/4` and `Matrix4`, mapped to native GPU types with `[Vector]`, `[VectorComponent]`,
  `[Matrix]` and `[MatrixColumn]`.
- `Shader.cs`: the shader, written against those types.

`YotsubaShader.Language.dll`, `YotsubaShader.Concepts.dll` and the syntax assemblies are embedded in the app as
resources (see `Playground.csproj`) because the runtime cannot expose raw metadata of Webcil assemblies. The
`Concepts` metadata is required because the syntax attributes inherit from `YotsubaShaderConcept`.

## Run it

```bash
cd Web
npm run playground      # dotnet publish + copy to src/static/playground-app/
npm run dev
```

Open http://localhost:4173/playground/ . The page finds `playground-app/_framework/blazor.boot.json` and connects by
itself. Without it, add `?demo=1` to preview the UI with sample data. The first load downloads roughly 80 MB
uncompressed (Roslyn Workspaces/Features are most of it; served compressed and cached afterwards).

## JSON contract

Files travel as `[{ "name": "Shader.cs", "source": "..." }]`. `Compile` returns:

```jsonc
{
  "ok": true,
  "diagnostics": [{ "severity": "error|warning|info", "message": "", "line": 1, "column": 1, "id": "CS0103", "file": "Shader.cs" }],
  "shaders": [{ "name": "BasicColorShader", "fullName": "BasicColorShader",
                "entryPoints": [{ "name": "Vertex", "stage": "Vertex", "returnType": "VertexOutput",
                                  "parameters": [{ "name": "input", "type": "VertexInput", "slot": "Location(0)" }] }] }],
  "spirv": { "text": "OpCapability Shader ..." },
  "outputs": [{ "name": "BasicColorShader", "stages": [{
    "name": "Vertex", "stage": "Vertex", "hlsl": "...", "glsl": "...",
    "glslEs": "...", "msl": "...", "cpp": "..."
  }] }]
}
```

`spirv.base64` is optional and is not populated by the current connected backend. Use the repository CLI when a binary
SPIR-V file is required.

Any other backend works too: call `YotsubaPlayground.setBackend({ name, compile, analyze?, complete?, hover?, signatureHelp? })`
before the page script runs (signatures are documented at the top of `src/static/js/playground.js`).

## Notes

- `bin/`, `obj/`, `.playground-out/` and `src/static/playground-app/` are build output and are git-ignored.
- Nothing here modifies the compiler projects; they are referenced by relative path.
